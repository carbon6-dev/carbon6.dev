Install

You need one head, and a worker on every machine you want agents to work on. The head can share a machine with a worker. Version 0.3.6 is the latest; see what changed.

Reading mail, documents and photos, and syncing Gmail, Calendar and Contacts, run in sandboxed kits on a worker with Docker or Podman, so give at least one worker either. Upgrading from 0.2: stop and remove c6m first (brew services stop c6m && brew uninstall c6m); the head takes its knowledge in when it starts.

macOS, with Homebrew

Bottles for Apple Silicon and Intel, for macOS 11 and later. They need neither Xcode nor the Command Line Tools. The services run as you, under launchd.

  • The head's config is $(brew --prefix)/etc/c6h/c6h.toml (kept across upgrades), its data $(brew --prefix)/var/c6h.
  • Sign in with c6h --config $(brew --prefix)/etc/c6h/c6h.toml login-link.
  • A worker: c6w enroll <token>, then brew services start c6w. It starts through a login shell, so sessions get your PATH.
  • Logs are in $(brew --prefix)/var/log/. brew upgrade upgrades them.

Ubuntu, with .deb packages

Built on Ubuntu 22.04 for amd64 and arm64, they install on 22.04 and every later release, with systemd units.

  • c6h runs as the c6h service and starts on install. Config: /etc/c6h/c6h.toml; state: /var/lib/c6h. Sign in with sudo -u c6h c6h --config /etc/c6h/c6h.toml login-link.
  • c6w (c6w_0.3.6_$arch.deb) runs as you, since sessions work on your files: c6w enroll <token>, then sudo systemctl enable --now c6w@$USER to start at boot, or systemctl --user enable --now c6w for your session.
  • c6 (c6_0.3.6_$arch.deb), the command line, on any machine that reaches the head.
  • Logs: journalctl -u c6h. Installing a newer package restarts its services; removing one keeps its data.

Other Linux

The four binaries, for amd64 and arm64, glibc 2.35 or later: carbon6-0.3.6-linux-amd64.tar.gz, carbon6-0.3.6-linux-arm64.tar.gz. Every file of a release is listed, with checksums, on its release page.

First run

  1. Sign in. Run c6h login-link on the head and open the link it prints (it works once, for 15 minutes). Add a passkey under Settings → Sign-in and use it from then on.
  2. Add a model. Add an LLM connection under Settings: an API key, your ChatGPT plan, Claude Code on the workers, or a local server such as Ollama (http://127.0.0.1:11434/v1, no key).
  3. Add a worker. On the Workers page, click Add worker and run the command it prints on the worker machine. Then start the worker's service, or run c6w run.
  4. Start a session on that worker, in a folder of your choice.

The head binds only loopback, private and tailnet addresses by default. To reach it from outside a tailnet or localhost, turn on HTTPS with ui_tls_head_ca = true. The guide covers this and everything after the first session.
